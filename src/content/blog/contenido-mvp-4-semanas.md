## Semana 1: acota el problema y define la métrica de éxito

Antes de tocar código, define a quién resuelves, cuál es el dolor prioritario y qué indicador probará tracción. Si no hay métrica, solo estás construyendo intuición.

## Semana 2: construye el flujo mínimo de punta a punta

No desarrolles módulos aislados. Crea un flujo completo, aunque sea simple: entrada, procesamiento y resultado visible para usuario.

- UI funcional, no perfecta.
- Back-end estable con validaciones básicas.
- Instrumentación para medir comportamiento real.

## Semana 3: activa usuarios y recolecta fricción real

Habla con usuarios mientras usan el producto. Las mejores mejoras no salen de una lluvia de ideas interna, salen de observar bloqueos concretos.

## Semana 4: prioriza mejoras con impacto y cierra el ciclo

Aplica ajustes de alto impacto, documenta aprendizajes y decide próximo paso con evidencia. Sin este cierre, el MVP se vuelve una beta eterna.
